# 听海 PRD v0.1

整理日期：2026-09-12。依据团队对话与既有材料；产品方向已明确，本文的范围细化为实施建议，尚不表示功能已完成。

## 1. 产品定义

听海：基于知乎知识内容的多风格音频讲解产品，支持收听时语音提问。

名字灵感来自“看山”与“听海”的呼应；采用独立产品界面。名称不代表知乎官方背书，尚未做商标或名称可用性核验。

团队明确要求：知乎搜索/Agent/知识库内容作为来源；多种音频风格，包含快板和双人播客问答；允许语音输入并针对节目实时提问。知乎直答是否作为生成环节、采用哪家 LLM/TTS/ASR，尚未选定。

## 2. 用户与价值假设

候选用户：想了解具体知识、在通勤或散步等场景不方便阅读的人。需求尚未通过正式访谈验证。

- 选择自己愿意听的讲述方式，降低开始学习的门槛。
- 听到疑惑时立即提问，回答能理解“刚才那个例子”。
- 查看节目来源，分清资料事实与情境化讲述。

成功不能只以播放完成率判断；小样测试还要询问是否愿意继续、能否用自己的话解释核心概念。

## 3. 首版范围

| 优先级 | 功能 | 验收条件 |
| --- | --- | --- |
| P0 | 输入主题、获取来源 | 返回相关资料；不足或失败时明确提示；摘要不标成全文 |
| P0 | 快板、双人播客两种风格 | 讲稿结构与声音表现有区别；各有可用节目；快板效果不达标则先与团队决定替换风格 |
| P0 | 生成讲稿与音频 | 展示真实阶段；至少一个完整节目可生成、播放 |
| P0 | 播放器与章节 | 播放、暂停、进度、章节切换；支持基本讲稿/章节文本 |
| P0 | 按钮触发语音提问 | 暂停节目、录音、识别、结合当前内容回答、播放回答、恢复原位置 |
| P0 | 来源与异常降级 | 来源可打开；麦克风不可用可文字提问；配音失败可读文本回答 |
| P0 | 公网交付 | HTTPS 下电脑和手机各跑通；密钥留在后端 |
| P1 | 精确字幕、历史、编辑与下载 | 核心链路完成后评估 |

首版建议每期 5–8 分钟，单主题、少量来源，首轮示例可更短。不做自建向量库管理、账户同步、声音克隆、支付、复杂背景音乐及自动监听插话。

## 4. 核心流程

输入主题 → 选择风格 → 检索与校验 → 讲稿/章节 → 分段配音 → 收听 → 暂停提问 → 回答 → 恢复。

“实时”首版指收听过程可按按钮发起问题，不能宣传为零延迟或全双工。材料不足时不凭空补成有来源的节目。回答引用当前节目及资料；需要新检索时显示正在查找补充资料。

## 5. 内容要求

- 快板稿需节奏、押韵、可懂度；普通 TTS 念押韵稿不等于快板表演。
- 双人播客明确讲解者与追问者职责，避免重复附和和空洞寒暄。
- 核心事实、数字与来源逐项对应。虚构人物、连接情节标为情境化改编。
- 不把历史人物的生成台词当作真实引语。
- 公共文件可检索不等于可以改编、配音、再分发；素材授权作为公开演示前置条件。

## 6. 首版验收脚本

1. 输入已核验示例主题，选择风格，查看来源及生成状态。
2. 播放真实生成的节目，暂停、切章节后能继续。
3. 中途问“刚才那个例子为什么成立”；回答联系当前段落，不只泛泛解释。
4. 回答播放结束后按继续，回到提问前节目位置，两条音轨不重叠。
5. 测试材料不足、检索失败、录音拒绝、识别为空、TTS 失败。
6. 电脑和手机各完成一次，记录实际耗时与费用，不用估计值冒充实测。
