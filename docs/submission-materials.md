# 听海 · 产品提交文案素材

## 一句话介绍

听海把知乎里有出处的知识变成一档可以随时插话的个人播客：选一个问题，选择听法，边听边问。

## 用户问题

知识搜索已经能快速给出文字答案，但移动、通勤、做家务等场景不适合持续盯屏；普通播客又是单向内容，听众遇到没听懂、想追问的地方只能先记下来。用户需要的不是把一段回答机械朗读出来，而是一个有来源、能讲清楚、还能在播放中回应自己的知识节目。

## 产品方案

听海连接知乎搜索、热榜、知识库、全网搜索和知乎直答，把真实来源组织成可核验的知识回答，再根据用户选择改编成单人讲解、双人播客、第一人称、评书或快板。首章准备完成即可进入播放器。用户长按“问一句”会立即暂停节目，主持人听完问题后直接回答，再回到被打断的位置继续。

## 与传统搜索 Agent 的差异

- 搜索框是内容入口，播放器才是主要界面。
- 输出单位是一档有章节、节奏、角色和声音的节目，不是一串聊天气泡。
- 回答保留来源，讲稿中的事实段落能够追溯到检索材料。
- 用户在收听现场插话，系统理解当前章节和此前节目上下文。
- 首页用主题节目和知乎热榜降低提问门槛，也支持用户从自己的问题开始。

## 技术亮点

1. 多来源检索结果去重并映射统一引用编号，未知编号不会伪装成真实引用。
2. 双人播客提示词把接话、打断、共同举例、观点修正和角色反差操作化，减少轮流读稿感。
3. 豆包语音播客负责双人音频，TTS 2.0 负责其他风格；首章就绪后即播。
4. Seeduplex 在同一会话中完成识别、回答和语音，并可以在节目材料不足时调用知乎检索。
5. 双工失败时回退到 ASR 2.0、知乎直答和 TTS，保留基本可用性。
6. 服务端签名上下文限制后续请求；密钥不进入浏览器；API 日志自动脱敏。

## 推荐演示流程（约 3 分钟）

1. 打开发现页，左右滑动五个主题分类，任选一档预置节目。
2. 展示“准备首章”动画后进入一屏式播放器。
3. 播放双人对话，切换讲稿，展示当前朗读句高亮和来源入口。
4. 长按“问一句”，在一个具体知识点上追问；松手后听主持人现场回答。
5. 回答结束后展示原节目继续播放，再演示收藏与最近收听。
6. 返回热榜，选择实时话题，展示检索材料、回答和讲述形式位于同一确认流程。

## 可量化的当前成果

- 5 个内容分类、15 期预生成节目。
- 5 种讲述形式。
- 3 种知乎直答模式，4 类主要内容来源。
- 8 个已配置节目音色；双人选择互斥。
- 自动化测试覆盖鉴权、引用、流式响应、语音协议、播放器、双工中断、超时与回退。
- 本地完整 API 日志同时提供 JSONL 和 `.log`，便于演示故障追溯。

## 价值

对用户，听海让需要盯屏阅读的知识转化为可在碎片时间消费的声音，并保留随时追问的主动权。对知乎，它让高质量回答与知识库内容进入新的使用场景，同时通过可点击来源把听众带回原始内容。对创作者，未来可以把优质回答组合成新的音频栏目，并获得更长的内容生命周期。

## 当前边界与后续方向

- 预置节目已随仓库提供，本地可以直接播放；公网部署需要对象存储承载音频。
- OAuth 已有接口骨架，正式登录需要公网 HTTPS 回调和进一步协议验收。
- “大家在听”当前保持真实空态，后续只展示用户主动公开的节目。
- 历史、收藏和本机昵称目前保存在浏览器，后续再做跨设备同步。
- 正式发布前需要确认第三方封面、知乎内容改编和 IP 素材使用规范。
